# kiewer v1 scope

The decisions behind v1, settled in the design grilling of 2026-10-30, grouped by area. Question codes (Q1, S3, N7) refer to that grilling. The four ADRs in `docs/adr/` carry the decisions that were hard to reverse; this file carries the rest. Vocabulary is in `GLOSSARY.md`.

## Product

- Name: kiewer. Hostname `kiewer.drwil.co`, staging `kiewer-staging.drwil.co`, both under the existing `*.drwil.co` certificate at Fastly. (Q1, Q54, Q60)
- Audience: people sharing KiCad designs on Discord. Discord link embeds are a first-class output. (Q10, Q23)
- Licence: MIT OR Apache-2.0. (Q15)
- In v1: board and schematic viewing, uploads, branches and forks, three sign-in providers, public and unlisted designs, Markdown descriptions, per-file downloads, thumbnails, net highlight, reference-designator search. (Q5, Q6, Q45, Q46, Q48, Q49)
- After v1: private designs, import from GitHub, Codeberg and gists, comparing revisions, named revisions (tags), zip download, search, zone filling, server-side geometry cache. (Q6, Q17, Q67, Q69, Q49, Q47, Q19, Q18)

## Workspace

- One Cargo workspace: `kicad-core` (parser, model, geometry, tessellation; compiles to wasm32 and native, no tokio, no web-sys), `viewer` (wasm-bindgen, wgpu on a canvas), `server` (axum). (S1)
- Pages are server-rendered HTML (askama or maud) with a little plain JavaScript for forms and the upload flow; wasm runs only inside the viewer canvas. (Q9)

## Rendering

- wgpu, one code path at the WebGL2 floor, WebGPU when present. See ADR 0001. (S3) The one exception, `max_texture_dimension_2d` from the adapter, is built as #94: the browser's device asks the adapter's limit (`browser_device_descriptor` in `kiewer_viewer/src/web.rs`), and `Viewer.create` and `resize` set the canvas to the size the page asks, capped past that limit with its aspect kept by `cap_canvas` in `kiewer_viewer/src/render.rs`; the browser stretches a capped canvas, so the page script turns a pointer into device pixels by canvas width over displayed width, never by `devicePixelRatio`.
- Tessellation in the browser at load with lyon: arcs, round-capped tracks, zones with holes, stroke-font glyphs. (Q18)
- Zone fills: stored fills only; an unfilled zone draws its outline hatched and the design page shows a warning. (Q19)
- Views: the eight stacks from the hand-off README as presets, free per-layer toggles and opacity on top, state in the URL fragment. Per-design presets later. (Q37) Built as #6: the layers, the views per board (one per copper layer, the front and the mirrored back as built, both sides either way up: the eight for a four-layer board) and the fragment (`view=5&F.Cu=0.5&F.SilkS=off`) are `kiewer_viewer/src/view.rs`; every layer is one slice of one scene (`scene.rs`) coloured per draw (`render.rs`), so a toggle never re-tessellates; the mask overlay is a polygon boolean in `kicad_core/src/tessellate.rs`, not a stencil pass; the panel is the layers block of `kiewer_lib/templates/viewer.html`. A new layer or view starts in `view.rs` and lands in those.
- Schematic: sheet list in a side panel, click on a hierarchical sheet symbol enters it, sheet path in the URL fragment. (Q38) One sheet is built as #12: the parser is `kicad_core/src/schematic.rs` with its model beside it, the drawing rules (pin text placement, field placement through the symbol's frame, label flags, the DNP cross, KiCad's default widths) are `kicad_core/src/tessellate/schematic.rs`, the colours are `kiewer_viewer/src/schematic.rs`, the page is `kiewer_lib/templates/schematic.html` at `/schematic` (the hand-off) and `/{handle}/{slug}/schematic` (a design's sheets, also under `/b/{branch}` and `/r/{hash}`). The sheet tree is built as #13: the sheet tree and the sheet path (sheet symbol names, a sibling's uuid where two share one, `sheet=power/reg` in the fragment) are `kicad_core/src/schematic/sheet_tree.rs`; the server parses every sheet of the revision and renders the tree as the panel's rows in `kiewer_lib/src/web/schematic.rs`, one row per node with its fragment and its blob's URL, so the page loads a sheet by fragment and a click on a sheet symbol (`Viewer::sheet_symbol_at`) is a move to the child's fragment. A revision with no board and a sheet opens on the schematic page (`DesignHead::opens_on_schematic`, the redirect in `web/design.rs`'s `show`, on the base, branch and revision forms alike); `?design` on those URLs keeps the design page, where the settings, the history and the upload links are, and is how the schematic page links back. The design page's schematic link names the branch or revision the page shows, as the redirect does (`schematic::url_at`, #69).
- Net interaction: hover names the net and dims everything else, softly and eased on a board; click pins a net at the full highlight, Ctrl or Cmd adds or removes further pinned nets, a tap always adds or removes, and each pin has its own colour; the net block lists the pinned nets, and a name folds open to its pads; Escape or a click on empty space clears all, and Ctrl or Cmd with Z steps back. Same for wires and labels on the schematic, whose dim stays full and instant. (Q45; #88 has the levels, the gestures and the colours.) The board half is built as #9 and #88: the hit test is `kicad_core/src/hit.rs` (a grid over every pad, via, track and zone fill with a net, queried with a tolerance of a few pixels on the copper layers the view shows, a pad over a via over a track over a zone), the net's pads, the footprint lookup and the net-only board beside it; the model both pages share is `kiewer_viewer/src/pick.rs` (the hovered net, the pinned nets with their colour slots, 50 steps of undo, the strength of each lit net and the dim; a change eases over 150 ms on a board and lands at once on a sheet or under `prefers-reduced-motion`, and frames run only while a fade is in progress); the highlight is `kiewer_viewer/src/highlight.rs` (the scene's draws dimmed through their colour, each lit net's zones and the rest tessellated once per net as separate meshes, `Tail` holding them after the scene's geometry with the pins first and writing only from the first net that changed, so a hover sweep leaves the pins where they are, and `Ramp`, the slot colours in OKLCH); the tooltip, the net block (one row per pin, a name folding open to its pads) and the search box are the net block of `kiewer_lib/templates/viewer.html`, with its own pointer listeners beside the page script's (`kiewer_lib/assets/kiewer_viewer_page.js`). The schematic half is built as #13 (#59's work): net membership on a sheet is `kicad_core/src/schematic/connect.rs` (the connections the drawing shows, without KiCad's ERC: coinciding connection points, a point on a wire's body, invisible power pins, and names across the sheet for global labels and power symbols, local labels, and hierarchical labels; names by KiCad's driver priority), the hit test `kicad_core/src/schematic/hit.rs` (a list scanned by box: a pin over a sheet pin over a junction over a label over a wire), the highlight `kiewer_viewer/src/sheet_highlight.rs` (the same `Pick` in its flat form, the sheet's draws dimmed, each lit net's geometry from `Tessellator::sheet_net` in the board's `Tail`, the slot colours from a darker `Ramp` tuned on the paper to lightness 0.48 and 0.54), and the net block of `schematic.html` over the same `Viewer` methods as the board's. A Ctrl or Cmd click inside a sheet symbol does nothing, so it enters no sheet. Nothing joins across sheets: a global or hierarchical name is the same on every sheet it appears on, which is as far as the names say.
- Search box: reference designator pans to the footprint or symbol. No measure, ruler or BOM tools. (Q46) Built as #9 for the board: the reference is matched whatever its case, the footprint framed with 30% of the viewport free around it (`Camera::frame`), and a miss said in the page. The same for a symbol on a sheet as #13 (`find_symbol` and `symbol_bounds` in `kicad_core/src/schematic/hit.rs`, the body and pins framed, texts aside).
- Zoom: world point under the cursor stays put (`t' = p - (p - t) * k`), exponential zoom from normalised wheel delta, non-passive wheel listener with `preventDefault`, trackpad pinch arrives as wheel with ctrlKey, two-pointer touch pinch with `touch-action: none`, camera in f64 on the CPU. Bindings follow KiCad: wheel zooms, ctrl+wheel pans horizontally, shift+wheel vertically, middle or right drag pans; keyboard plus and minus zoom at the view centre; fit-to-board; double-click zooms at the cursor. (S10) The listeners, the resize and the zoom read-out are `start` in `kiewer_lib/assets/kiewer_viewer_page.js`, the page script both pages import with their canvas and their load (#54); the camera is the wasm's.
- Net labels: text height is 0.7 × track width, never shrunk to fit length; a run gets a label only when its length is at least 1.3 × the text length; a label draws when its text height on screen reaches about 7 px, fading in over the next 50%, with the threshold applied in the vertex shader; one label per run, repeated every ~8 text lengths; collisions resolved once at parse with priority pads, vias, zones, tracks (shift along the run, then drop); via labels capped to the via diameter and shown at higher zoom; one zone label at the pole of inaccessibility; pads show number first and net second only when both fit; angles in (-90, 90] with near-vertical reading bottom to top; mirrored back views flip x and negate angles. Toggles per class and a threshold slider. Constants tuned against `exports/png` in the hand-off. (S11) Built as #8: every rule and its constant is `kicad_core/src/labels.rs` (runs, the gate, the repeats, the pole of inaccessibility, the one-time collision resolution), run once at load, with two constants the rules left open: a pad's net joins its number only when their shared height is at least half the number's own, and a zone label is at most 2 mm tall; the glyph meshes and the per-character instances are `kiewer_viewer/src/labels.rs`, the instanced pass whose vertex shader applies the label gate and the mirror is `kiewer_viewer/src/render/label_pipeline.rs`; the toggles and the threshold are the label settings of `kiewer_viewer/src/view.rs`, carried in the fragment as `labels=10&via.net=off`, and the labels block of `kiewer_lib/templates/viewer.html`. A change to a rule starts in `labels.rs`; a change to how a label looks on screen in the pass.
- Fonts: text naming no face renders in Newstroke. A design naming a face the browser lacks shows a warning and a picker; availability is detected by canvas text measurement against a fallback, since `document.fonts.check()` returns true for unknown system fonts and `queryLocalFonts()` is Chromium-only. The picker probes a fixed list of common faces per platform, offers free text, and defaults to the stroke font. The choice is kept per browser in localStorage keyed by font family. System faces render through a Canvas2D glyph atlas. (S9, Q12, Q50) Built as #10: the probe, the picker and the atlas drawing are the fonts block at the end of `kiewer_lib/templates/viewer.html`; the layout of a text in an outline face (KiCad's anchor rules, em = 1.4 heights) is `kicad_core/src/font/outline.rs`; the packing, the rasterisation size (a power of two pixels per em from the camera's scale, rebuilt when the view wants more or less than a quarter) and the quads are `kiewer_viewer/src/atlas.rs`; the textured pass is `kiewer_viewer/src/render/atlas_pipeline.rs`. A change to how a named face is found or drawn starts in those four.
- Newstroke's glyph table (`kicad_core/src/font/newstroke.txt`, one glyph a line) is regenerated by `newstroke_dev` from Vladimir Uryvaev's CC0 release of the font sources (the KiCad legacy symbol libraries the glyphs were drawn in), with the release's own conversion rules, so every glyph stays CC0. The CJK ideographs KiCad added from Source Han Sans (OFL) are left out: they exist only in KiCad's GPL-licensed generated table, and they are 2.6 MB of its 2.9 MB; a character without a glyph draws as `?`. Text layout follows KiCad's `FONT::Draw` rules (size, pen width, justification, interline, rotation, mirror, upright folding for footprint text); a knockout is the text's box less the union of its strokes. The about page carries the credit and the CC0 notice. (#5) A native build includes the table; the wasm leaves it out, and the page fetches it as a hashed static asset while the wasm loads and hands it to `Viewer.create`. (#41)
- Telemetry: one `navigator.sendBeacon` per page load after adapter init with backend, whether `navigator.gpu` existed, outcome or failure reason, and adapter vendor when exposed; wasm panics go to the same endpoint, and so does a canvas capped to the device's texture limit, once per page load as outcome `capped` with no reason and no sizes (#94). The server validates, rate-limits per IP, and emits one structured log line; a Cloud Logging log-based metric charts it. No identifiers, no cookie. Nothing else phones home: no email, no page analytics, no third-party error service. (S3, Q53) Built as #11: the endpoint, its shape and its limits are `kiewer_lib/src/web/beacon.rs`; the page's send is `kiewer_lib/assets/kiewer_viewer_page.js`, the page script the board and schematic pages share (#54), whose panic hook is set before the wasm is fetched and shows and sends a panic the moment it happens, and whose import of the viewer's script sits inside its failure path, so a script that fails to load shows and sends `failed` with backend `none` and reason `import: <message>` (#96); the metric is `infra/logging.tf`. A change to what the beacon carries starts here and lands in those three.

## Storage and history

- Data model per ADR 0002: blobs, trees, revisions, branches, `design_revision`, `blocked_blob`. (Q42, Q62)
- Hashes: SHA-256; short form is the first 8 hex characters, extended when ambiguous within a design. (Q30)
- A revision records author (account id), time, optional message, parent, and parsed metadata. No diff. (Q31)
- Default branch `main`, renamable by owner or admin. (Q32)
- Fork: full default branch by default, or all branches; records the source design and revision. Forking your own design is allowed under a new slug. A fork points at existing revision rows. (Q33, Q55) Built as #20: the one transaction (the source's row and branches held, the design row at the next free slug with the source's name, default branch and visibility and no description, the branches copied with the times their heads last moved, the fork's `design_revision` rebuilt by walking their chains) is `kiewer_lib/src/fork.rs` over new functions in `design.rs`; the fork source columns are the `20261102162000` migration; the POST is `kiewer_lib/src/web/fork.rs` and the form and the forked-from line are the fork block of `kiewer_lib/templates/viewer.html`. No fork count or list is shown. A change to what a fork takes or inherits starts in `fork.rs`.
- Push: the upload form selects a branch, defaulting to the branch of the page it was opened from, with a "new branch" entry. The parent is the head at write time, set by compare-and-set. If the head moved, the upload becomes a pending revision for an hour and the uploader chooses re-append (parent rewritten to the new head, hash recomputed) or branch (new branch at the old head). (Q63) Built as #19: "moved" is measured from the head the upload was built on, which is the revision its form was opened at when that sits on the branch pushed to (the hidden `from` and `seen_on` fields, so an upload from behind the head is held too), else the head `upload::push` reads before the parse; the transaction holds the branch's row and compares. The pending row and the decision are `kiewer_lib/src/pending.rs` over the `20261103100000` migration; the choice page is `kiewer_lib/src/web/pending.rs`. A decision stamps the revision with its own time, meets the account cap and the block list again, and spends no allowance: the upload did when it arrived. A re-append names the head its page showed, so a head that moved again is refused and the page shows it, rather than landing on a revision the uploader never saw. A change to what is held or chosen starts in `pending.rs`. Built as #62: the branch list is the picked design's. Picking another design in the form loads it again for that design (a script on `upload.html`), keeping a branch of the same name and dropping the opened revision; with scripts off the list stays the opened design's.
- History page `/{handle}/{slug}/b/{branch}/history`: newest first, thumbnail, ordinal, short hash, author, time, message, metadata line. The viewer header has a branch dropdown and a revision dropdown with the last ten. Off the head, a one-line banner names the branch, the distance behind, and links to the head and "new branch here". (Q64, Q65, Q66)
- Branches page `/{handle}/{slug}/branches`: head, ordinal, age, author; delete, rename, set-default by role; the default branch cannot be deleted while default. (Q68) Built as #19: the rules and their transactions are `kiewer_lib/src/branch.rs` (`Allowed` is who may do what; a collaborator's own branches are the ones `branch.created_by` names), the page is `kiewer_lib/src/web/branches.rs`. It renders the same for everyone, the forms hidden, and its script opens them from `/branches/allowed`, which answers for the session (ADR 0003). New-branch-here is its `?from=` form: one branch row, no revision, and no move in the listings. Deleting a branch takes the revisions only it reached out of `design_revision` at once and drops any pending revision aimed at it.
- Delete: hard delete of the design's rows at once, Fastly purged; the collector runs nightly with a 24-hour grace. Account delete hard-deletes owned designs, removes role rows and sessions, reserves the handle 90 days; forks by others survive with the old handle as text. (Q35, Q43) Built as #23 and #86: the two deletes are `kiewer_lib/src/delete.rs`, their forms `kiewer_lib/src/web/delete.rs` (the design's inside the design page's settings block, its name typed out; the account's in settings, its handle typed out, with the designs other people are on listed first). The collector is `kiewer_lib/src/collector.rs`, whose module doc says why a concurrent upload is safe: a blob reaches the store through `collector::store` alone and a tree through `design::record_tree`, each of which claims the row, and the 24 hours count from `claimed_at`. Cloud Scheduler POSTs `/api/collector` nightly behind the thumbnail retry's token (`infra/run.tf`). A blob's object is deleted after its row, from the `blob_removal` queue the row's delete wrote. A later way of changing a handle has to read `reserved_handle`, as `account::choose_handle` does. Built as #31: the same run then removes every session past its expiry and every account with no handle older than 24 hours, with its identities; a person whose sign-up was swept signs in again and gets a fresh account, silently.
- Compression: blobs stored gzip in GCS with `Content-Encoding: gzip`; hash and caps apply to uncompressed bytes. (Q20)

## Uploads

- Transport: one multipart POST per revision through Fastly to Cloud Run with HTTP/2; the server streams parts to temp files, parses, gzips, hashes, writes GCS, then writes rows in one transaction. (Q40)
- Only `.kicad_pcb`, `.kicad_sch` and `.kicad_pro` are kept. Other files are dropped silently, at most a console warning. A KiCad-named file that fails to parse is rejected with the error. KiCad 9 and 10 formats (board `20241229` and later); older files are rejected naming the version and suggesting a re-save. (Q4, Q11)
- Dropped files, dropped folders and zips. A zip is expanded by the upload page, never by the server (ADR 0005): the page reads its central directory, checks the entry count (10,000), the 50 MB and 200 MB caps and the skip list against it before any inflate, inflates only the kept entries (store and deflate) and sends them uncompressed with their paths, as a folder drop does; a zip's own size counts for nothing. An encrypted entry, zip64 records or another method is denied on the page, and so is a zip sent with scripts off (the server refuses the part). Skipped: `*-backups/`, `*.lck`, `~*.lck`, `*-save.kicad_*`, `_autosave-*`, dot-directories, `__MACOSX/`. The tree is rooted at the project folder with relative paths kept. More than one project in one upload: the shallowest is taken and a warning names the others. Everything under the taken project's folder is kept, a project nested in it included, since a project may keep sheets, or another project's folder, in a subfolder; a project beside it, outside that folder, is left out with a second warning. (Q41, N3; the nested case settled in #84) Built as #17: the skip list is `upload::skipped`; the rooting and its warnings are `root_at_project_folder` in `upload.rs`, carried to the page by `Pushed::warnings`; the folder picker and the drop are the script in `templates/upload.html`, which names every part by its relative path and leaves behind what the server would not keep, so a large `.git` does not count against the body limit. Built as #83: the zip reader is that script too; the server's refusal of a zip uploaded by itself is `Incoming::refuses` (`Refusal::ZipPart`), and a zip inside a folder is a backup or an archive beside the project, dropped like any other file that is not kept.
- Caps: 50 MB per file, 200 MB per revision after extraction, 2 GB per account, 30 s parse timeout, 30 revisions per account per hour answered with 429 and Retry-After. (Q13, Q44) Built as #17: the hourly allowance is `kiewer_lib/src/rate_limit.rs`, counted from the revision rows and the `upload_refusal` rows, so a refused upload spends it too and a hostile one cannot repeat freely; checked by the upload handler before the body is read and by `upload::push`. Built as #45: the route's body limit (`upload::BODY_LIMIT`, the revision cap plus 1 MiB of framing) counts the dropped files too, so passing it is a refusal of its own (`Refusal::UploadTooLarge`), naming the 200 MB cap and telling the uploader to leave out what is not a KiCad file.
- Server-side parse with `kicad-core` at upload stores metadata: format version, layer count, board size, fonts used, net and footprint counts. (S8)

## Accounts and access

- Sign-in with GitHub, Discord and Google via the `oauth2` crate plus a userinfo call per provider (Discord the `identify` scope alone against `/users/@me`: the snowflake and the username, no email). One account; providers linked explicitly from settings; a first sign-in with an unknown provider makes a new account. (S6, Q7)
- Sessions: Postgres rows, random id in an HttpOnly Secure SameSite=Lax cookie, 30-day sliding expiry, listed and revocable in settings. (Q36)
- Handle chosen at first sign-in, prefilled from the provider, lowercase letters, digits and hyphens, no rename in v1. Slug derived from the name, editable by owner or admin, old slug redirects until reused. (Q28, Q29)
- Roles: collaborator pushes revisions and manages own branches; admin does that on any branch and manages people, name and description; owner alone deletes, transfers and changes visibility. One owner per design. (Q8, Q34)
- Visibility: public or unlisted. Unlisted appears in no listing. Authorisation only on writes. (Q6, S7)
- Separate OAuth registrations per environment (production, staging, development). Production and staging secrets in Secret Manager mounted into Cloud Run; development in a git-ignored `.env`. (Q57)

## Pages and URLs

- `/{handle}/{slug}` head of the default branch; `/b/{branch}` branch head; `/r/{hash}` a revision checked against the design; `/r/{hash}/f/{path}` one file with its original filename and a `Content-Disposition`, cached under the revision hash; `/blob/{hash}` raw bytes; `/{handle}` a person's public designs; `/` recent public designs; `/{handle}/{slug}/people` the people page, for an admin or the owner, private; `/{handle}/{slug}/branches` the branches page; `/{handle}/{slug}/pending/{id}` a pending revision's choice, for its uploader, private. No search. (Q27, Q47, Q49)
- Description: Markdown via comrak (CommonMark plus GitHub tables and strikethrough); allowed output is headings, paragraphs, emphasis, lists, http and https links with `rel="nofollow noopener"`, inline code and code blocks, blockquotes, tables; no raw HTML, images or embeds; rendered HTML cached in the row. (Q48, Q56) Built as #22: the allow-list and the exact comrak options are `kiewer_lib/src/description.rs` (every node kind not listed there is dropped before rendering, an image or a refused link leaving its text); the row holds the Markdown and the HTML, rendered again at every save; the slug's rules, the slug change and the redirect an old slug leaves until a new design takes it are `kiewer_lib/src/slug.rs`; the one transaction saving name, slug and description is `kiewer_lib/src/design_settings.rs`; the form is the settings block of `kiewer_lib/templates/viewer.html`, its POST `kiewer_lib/src/web/design_settings.rs`, which lands on the design page, with `?design` for a head that opens on its schematic (#70). A change to what the description may contain starts in the allow-list.
- Thumbnails per ADR 0004. Open Graph tags on design, branch, revision and schematic pages. (Q10, Q21, Q22, Q23) Built as #25: a PNG is a blob outside any tree and the `thumbnail` row keys the two by revision (`kiewer_lib/src/thumbnail.rs`); served at `/{handle}/{slug}/r/{hash}/thumbnail/{1200x630,400x400}.png`, under a design as ADR 0002 asks. The render budget is 5 s; past it, or when a render fails, a Cloud Tasks task POSTs `/api/thumbnails/{hash}`. A revision with a blocked file shows the placeholder.

## Caching

- Fastly per ADR 0003: two origins, identical pages, `/api/me`, `Surrogate-Key` purges (design id, handle), `private, no-store` for settings and upload pages. (Q24, Q25, Q26)
- Static assets: content hash in the filename, `Cache-Control: public, max-age=31536000, immutable`, brotli and gzip prebuilt. (Q39)
- The server also serves `/blob/*` from its store so development works without Fastly; in production Fastly answers first. (N6)
- Built as #26: `kiewer_lib/src/cache.rs` holds the policies and which write purges which keys (its `Key` doc). Every response a handler builds names a `Policy`, a page goes through `cache::page` with its keys, and a write ends with `cache::after_write`. A new handler follows that, and the session byte test in `kiewer_lib/tests/it/cache.rs` has a case per cacheable page, so a new one adds its case. A cacheable page reads nothing of the session.

## Operations

- GitHub Actions: fmt, clippy, tests and the wasm build on every push; every push to main pushes the image to Artifact Registry and deploys staging; a green run whose Version sorts above every Release tag deploys production and tags the commit; both via Workload Identity Federation with no stored keys; follows the operator's release conventions. (Q14, Q58)
- Region europe-west4 for Cloud Run, Cloud SQL and buckets. (Q16)
- Terraform in `infra/` for GCP and Fastly, state in a GCS bucket, applied by hand from a workstation; CI deploys only Cloud Run revisions. A deploy switches traffic after a health check; rollback is traffic back. (Q51, Q58)
- Staging: own Cloud Run service, database `kiewer_staging` on the shared instance with its own migrations, own bucket. A script copies production in on demand: pg_dump and restore, server-side GCS copy of every blob the restored trees name, sessions and OAuth identities dropped, developers granted ownership of copied designs by a one-off grant in the script. (Q59, Q61)
- Local development: a blob-store trait with a filesystem implementation for development and tests and the GCS implementation in production with one integration test; Postgres from docker compose; sqlx offline mode in CI. (Q52)
- Postgres over the Cloud Run unix socket `/cloudsql/<instance>`, `sqlx` with migrations. (S4)
